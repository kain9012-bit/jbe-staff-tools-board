# 게시글 요약 작성 지침

「교직원 제작 도구 현황」 도구 상세 화면의 **한눈에 보기**에 들어가는 요약을 쓰는 기준.
교직원 제작 도구(BBS_0000683)와 교육청 배포 도구(BBS_0000649) 두 게시판 모두 같은 기준으로 작성.
새 게시글이 올라올 때마다 이 지침 그대로 작성해 구조와 말투를 맞춤.

## 1. 원칙

- **본문 비게재:** 원 게시글 본문은 화면에 싣지 않음. 정해진 항목으로 정리한 요약만 게재
- **글과 그림 모두 확인:** 설명을 그림으로 올린 글이 많음. 본문 글, 본문 그림, 그림 첨부파일을 모두 읽고 정리
- **원문 근거:** 게시글의 글·그림·첨부파일 이름·링크에 있는 내용만 사용. 추측·보충 금지
- **명사형 끝맺음:** "~함", "~합니다" 대신 명사로 끝냄 (예: "자동 계산", "일괄 생성")
- **짧고 간결:** 항목마다 한 줄. 길면 줄여서 다시 씀
- **빼는 것:** 비밀번호·암호키·교사 PIN, 전화번호·메신저·이메일 등 연락처, 사람 이름, 홍보 문구, 이모지
- **원문 문장 복사 금지:** 짧게 다시 씀

## 2. 항목

| 항목 | 키 | 필수 | 기준 |
|---|---|---|---|
| 한 줄 소개 | `what` | 필수 | 무엇을 해 주는 도구인지. 45자 이내. 업무 대상 + 하는 일 |
| 만든 이유 | `why` | 권장 | 어떤 불편을 줄이는지. 70자 이내. 게시글에 없으면 생략 |
| 주요 기능 | `features` | 필수 | 3~6개(설명이 짧으면 1~2개). 각 45자 이내. 사용자가 얻는 결과 위주 |
| 사용 순서 | `steps` | 필수 | 2~5단계. 각 50자 이내. 처음 여는 것부터 결과를 얻기까지 |
| 실행 방식 | `run` | 필수 | 아래 8가지 중 하나 |
| 필요한 것 | `needs` | 선택 | 0~3개. 계정·API 키·브라우저·운영체제·원자료 파일·암호 확인 등 |
| 유의사항 | `cautions` | 선택 | 0~3개. 지원 범위, 시험판, 저장 위치, 개인정보, 오류 조건 등 |
| 정리 근거 | `basis` | 필수 | `글`, `그림`, `글·그림` 중 실제로 내용을 얻은 곳 |
| 설명 부족 | `thin` | 선택 | 글·그림을 다 봐도 설명이 몇 줄뿐일 때 `true` |
| 설명 없음 | `empty` | 선택 | 글도 그림도 없어 요약할 내용이 없을 때 `true` (다른 항목 생략) |
| 정리한 날 | `at` | 필수 | `YYYY-MM-DD` |

### 실행 방식 8가지 (`run`)

| 값 | 판단 기준 |
|---|---|
| 웹 접속 | 주소로 접속해 바로 쓰는 사이트 |
| HTML 파일 | 내려받은 .html 파일을 브라우저로 여는 방식 |
| 브라우저 확장 | 크롬·엣지 확장 프로그램 (개발자 모드 로드 포함) |
| 설치 프로그램 | .exe 등 PC에서 실행하는 프로그램 (설치 없는 실행 파일 포함) |
| 북마크 | 북마크바에 끌어다 놓고 누르는 방식 |
| 구글 시트 | 구글 시트 사본·앱스 스크립트 기반 |
| AI 챗봇 | 커스텀 GPT, 노트북LM 등 대화형 AI |
| 기타 | 위에 해당하지 않거나 게시글로 판단 불가 |

판단이 둘 이상이면 사용자가 **처음 여는 방식**을 고름.

### 자주 쓰는 표현

- 필요한 것: `크롬·엣지`, `윈도우 10·11`, `구글 로그인`, `ChatGPT 계정(커스텀 GPT)`, `Gemini API 키`, `블로그에서 1일 암호 확인`, `나이스 명단 엑셀`
- 유의사항: `테스트 버전`, `시험판`, `전북 K-에듀파인 전용`, `입력 내용은 브라우저에만 저장`, `외부 전송 없음`

## 4. 새 게시글 요약 절차

1. **새 글 모으기:** 사용자 PC에서 `python tools/fetch_new_posts.py` 실행
   - 두 게시판 수집 시트의 '게시중' 글 가운데 `src/data/summaries.json`에 없는 글만 대상
   - 한 게시판만: `--board staff` 또는 `--board official`
   - 글: `_probe/sum/new_posts.json` (본문·첨부파일 이름·링크·그림 목록)
   - 그림: `_probe/sum/img/<dataSid>/` (본문 그림과 그림 첨부파일, 줄인 사본)
   - 특정 글만 다시 모으기: `python tools/fetch_new_posts.py 1186819`
2. **글과 그림 읽기:** 본문을 읽고, 그림을 한 장도 빠짐없이 확인. 그림 속 기능·사용 순서·조건을 요약에 반영
3. **요약 작성:** 2·3장 기준
4. **저장:** `src/data/summaries.json`의 `items`에 `dataSid`를 키로 추가. 기존 항목은 고치지 않음
   - **교육청 배포 도구 새 글:** `src/data/official-meta.json`에도 한 줄 추가. 사용목적(행정업무·범용도구·교육활동·교무·학사), 적용기관(교직원 제작 도구와 같은 표기), 도구 구분(게시판 목록 값). 이 값이 없으면 도구 찾기에서 '분류 없음'으로 보임
5. **배포:** 깃허브에 올리면 Vercel이 다시 빌드해 화면에 반영

요약이 없는 글은 상세 화면에 "아직 게시글 요약이 없습니다."와 원 게시글 링크가 표시됨.
게시글이 크게 고쳐진 경우에만 해당 항목을 다시 쓰고 `at`을 새 날짜로 바꿈.
